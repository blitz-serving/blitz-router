# OSDI'26 Artifact Evaluation

This directory contains the AE entry points for reproducing the evaluation
figures for the OSDI'26 AE submission #11, "Simple is Better: Multiplication
May Be All You Need for LLM Request Scheduling."

The AE target is:

- reproduce Figure 21 from four trace/policy end-to-end CDF experiments;
- reproduce Figure 22 from the full scaling sweep;
- regenerate the corresponding PDFs with the scripts in `xmetric-plots/figs`.

## Repositories and Branches

Prepare all repositories under one parent directory and export it as `AE_ROOT`:

```bash
export AE_ROOT=/path/to/artifact-root
```

| Repository | Required branch | Purpose |
| --- | --- | --- |
| `blitz-router` | `osdi26-ae-workflow` | Rust router and `request-sim` submodule |
| `MetricsTestRunner` | `ae` | Experiment orchestration scripts; includes `sweep_test_robust.sh` |
| `yaullm` | `lmetric/step-reporter-v2` | Patched vLLM engine with step-level metrics |
| `xmetric-plots` | `ae` | AE-only plotting scripts and archived data for Figure 21 and Figure 22 |

Clone or verify the repositories:

```bash
cd "${AE_ROOT}"
git clone --recursive --branch osdi26-ae-workflow git@github.com:blitz-serving/blitz-router.git
git clone --branch ae git@github.com:blitz-serving/MetricsTestRunner.git
git clone --branch lmetric/step-reporter-v2 git@github.com:blitz-serving/yaullm.git
git clone --branch ae git@github.com:blitz-serving/xmetric-plots.git
```

The helper script does the same for missing repositories and reports branch
mismatches for existing checkouts without changing local work:

```bash
cd "${AE_ROOT}/blitz-router"
bash ae/setup_repos.sh
```

## System Architecture

`request-sim` replays a trace and sends OpenAI-compatible streaming requests to
the router. The router continuously collects realtime metrics from each
`yaullm` engine, updates the scheduling state, and forwards each request to one
engine. Responses stream back through the router to `request-sim`.

The key generated files are:

- `client.jsonl` or `client_*.jsonl`: per-request TTFT, TPOT, token counts, and
  status, generated by `request-sim`;
- `router_v2.log`: router-side routing, KV-cache, prefill, and decode metrics;
- copied TOML configs and command metadata in each timestamped experiment
  directory.

The plotting scripts under `${AE_ROOT}/xmetric-plots/figs` read experiment
directories from a data root. By default that root is
`${AE_ROOT}/xmetric-plots/data`, which contains the archived fast-path `.tgz`
files. For slow-path GPU reruns, `ae/run_slow_path.sh` writes symlinks to
`${AE_ROOT}/xmetric-plots/slow-data` and runs the same plotting scripts with
`XMETRIC_DATA_DIR` pointing to that slow-path data root.

## Hardware, Models, Traces, and Runtime

The paper's main experiments use a 16-GPU testbed with 16 vLLM instances. The
paper describes the testbed as 16 NVIDIA H20 GPUs, each with 96 GB HBM. The
runner scripts assume two machines with 8 GPUs each, SSH access between them,
and one vLLM instance per GPU.

Models can be downloaded into `${AE_ROOT}/models` or supplied from an existing
shared filesystem. The helper script uses Hugging Face by default:

```bash
cd "${AE_ROOT}/blitz-router"
bash ae/setup_models.sh
```

By default this downloads:

- `Qwen/Qwen2.5-7B-Instruct` to `${AE_ROOT}/models/Qwen2.5-7B-Instruct`
- `Qwen/Qwen3-30B-A3B` to `${AE_ROOT}/models/Qwen3-30B-A3B`

To use existing checkpoints or a different model mirror, override the
environment:

```bash
QWEN_7B_DIR=/path/to/Qwen2.5-7B-Instruct \
QWEN_30B_DIR=/path/to/Qwen3-30B-A3B \
bash ae/setup_models.sh
```

If the model files already exist on every worker node, skip the download and
set `MODEL_PATH_30B` and `MODEL_PATH_7B` in `MetricsTestRunner/ae.env` to those
existing paths.

Model mapping:

| Workload | Model in the paper | Runner model variable | Default AE model path |
| --- | --- | --- | --- |
| ChatBot (Qwen) | Paper label: Qwen3-30B; concrete AE checkpoint: Qwen3-30B-A3B | `qwen30b` | `${AE_ROOT}/models/Qwen3-30B-A3B` |
| Agent/API (Qwen) | Paper label: Qwen2-7B; concrete AE checkpoint: Qwen2.5-7B-Instruct | `qwen7b` | `${AE_ROOT}/models/Qwen2.5-7B-Instruct` |
| Coder | Paper label: Qwen3-30B; concrete AE checkpoint: Qwen3-30B-A3B | `qwen30b` | `${AE_ROOT}/models/Qwen3-30B-A3B` |
| ToolAgent (Kimi) | Paper label: Qwen3-30B; concrete AE checkpoint: Qwen3-30B-A3B | `qwen30b` | `${AE_ROOT}/models/Qwen3-30B-A3B` |

The paper text uses the shorter labels `Qwen2-7B` and `Qwen3-30B`. The
MetricsTestRunner launch scripts used for AE instantiate those labels with
`Qwen2.5-7B-Instruct` and `Qwen3-30B-A3B`, respectively.

Traces:

| --- | --- | --- |
| ChatBot (Qwen) | `sweep_test_robust.sh` TraceA entries | `qwen_traceA_blksz_16.jsonl` |
| Agent/API (Qwen) | `sweep_test_robust.sh` TraceB entries | `qwen_traceB_blksz_16.jsonl` |

The Alibaba/Qwen traces are from
`https://github.com/alibaba-edu/qwen-bailian-usagetraces-anon`:

```bash
cd "${AE_ROOT}/blitz-router"
bash ae/setup_traces.sh
```

The ToolAgent trace is from the Mooncake release:
`https://github.com/kvcache-ai/Mooncake/blob/main/FAST25-release/traces/toolagent_trace.jsonl`.
For AE, we normalized the official Mooncake trace into the same JSONL schema
used by the Qwen traces and `request-sim`, then uploaded the converted file to
`xmetric-plots/traces/mooncake_toolagent_trace_poissoned.jsonl`. Place or
symlink that file under `DATASET_DIR` with the same filename before running the
ToolAgent/Kimi experiments.

Each experiment point uses `TIME_IN_SEC=1200` by default in
`MetricsTestRunner/sweep_test_robust.sh`: about 20 minutes of client replay plus
vLLM startup, router startup, cleanup, and `client.jsonl` merge. In practice,
budget 25-35 minutes per policy/trace/scale point on one 16-GPU testbed. Retry
loops and cluster startup failures can increase runtime.

## Fast Path: Archived Data

This path does not require GPUs. It verifies that the released raw data can
regenerate the paper's Figure 21 and Figure 22.

```bash
cd "${AE_ROOT}/blitz-router"
bash ae/run_all.sh figures
```

This creates `ae/.venv`, installs the plotting dependencies, extracts the
needed `${AE_ROOT}/xmetric-plots/data/*.tgz` archives on demand, and writes PDFs
under `${AE_ROOT}/xmetric-plots/figs`.

The fast path was validated for:

- `figs/e2e-cdf-v1/qwen3-to-c.py`
- `figs/e2e-cdf-v1/qwen2-to-b.py`
- `figs/e2e-cdf-v1/qwen3-coder.py`
- `figs/e2e-cdf-v1/qwen2-mooncake-tool.py`
- `figs/scaling-test/scaling-fix-v1.py`

The paper includes manually marked copies of the four Figure 21 CDF panels
(`*-marked.pdf`) to highlight visual comparisons. The AE plotting scripts
regenerate the underlying unmarked panels (`*.pdf` and `*.png`) from the same
data; the curves and printed statistics are the reproduced results. Figure 22
is generated directly as `figs/scaling-test/scaling-fix-v1.pdf`.

## Slow Path: Full GPU Reproduction

Slow-path GPU reproduction uses `MetricsTestRunner` branch
`ae` and the robust sweep launcher
`MetricsTestRunner/sweep_test_robust.sh`. The launcher owns the full lifecycle
for every test point:

1. build `blitz-router` with the current policy feature;
2. inject the current trace, scale factor, model path, dataset path, and SSH
   settings into the 16-GPU TOML configs;
3. start 8 local and 8 remote `yaullm` vLLM instances;
4. wait for all vLLM logs to report startup success;
5. start the router and wait for port `58009`;
6. start `request-sim` for `TIME_IN_SEC`;
7. clean up local/remote vLLM, router, and client processes;
8. merge generated `client*.jsonl` into `client.jsonl`.

### Patched vLLM Environment

The slow path must use the patched `yaullm` checkout on branch
`lmetric/step-reporter-v2`; stock vLLM does not export the step-level metrics
consumed by the router. The expected executable is:

```bash
"${AE_ROOT}/yaullm/.venv/bin/vllm"
```

Create that environment from the patched `yaullm` source:

```bash
cd "${AE_ROOT}/blitz-router"
bash ae/setup_vllm_env.sh
```

The script creates `${AE_ROOT}/yaullm/.venv`, installs the CUDA vLLM
dependencies, installs the patched checkout in editable mode, and prints the
`VENV_PATH` line to put in `MetricsTestRunner/ae.env`. The script defaults to
`VLLM_USE_PRECOMPILED=1`, which matches the validated environment and avoids a
fragile local CUDA extension build. It also pins
`VLLM_PRECOMPILED_WHEEL_LOCATION` to a vLLM wheel compatible with the
`torch==2.7.1` dependency in `yaullm/requirements/build.txt`; using the latest
precompiled wheel selected by upstream vLLM can produce CUDA extension ABI
errors with this torch version. The first install downloads and installs large
PyTorch/CUDA/vLLM wheels, then repackages the patched vLLM editable package.
Depending on network and filesystem speed, it can take tens of minutes. If the
artifact environment uses a local wheel mirror, set
`VLLM_PRECOMPILED_WHEEL_LOCATION=/path/or/url/to/compatible.whl` before running
the script. On clusters with slow access to `wheels.vllm.ai`, predownload this
wheel once and point both local and remote installers to the local file.

If your artifact environment already provides a working patched vLLM
environment, you can skip the install and point `VENV_PATH` to it instead:

```bash
export VENV_PATH=/path/to/patched/yaullm/.venv
"${VENV_PATH}/bin/vllm" --help >/dev/null
```

The two-node 16-GPU setup supports both shared and non-shared filesystems:

- Shared filesystem: `VENV_PATH`, model paths, and `OUTPUT_BASE` may be the same
  on the local coordinator and the remote 8-GPU worker.
- Non-shared filesystem: install the patched `yaullm` environment on each node
  and set separate local and remote paths in `MetricsTestRunner/ae.env`.

For a non-shared remote worker, clone `yaullm` on that worker at branch
`lmetric/step-reporter-v2`, then run the installer through SSH with paths that
exist on the remote machine:

```bash
ssh -p "${REMOTE_SSH_PORT}" "${REMOTE_USER}@${REMOTE_HOST}" \
  'cd /remote/path/to/blitz-router && \
   YAULLM_DIR=/remote/path/to/yaullm \
   VLLM_VENV=/remote/path/to/yaullm/.venv \
   bash ae/setup_vllm_env.sh'
```

Then set `REMOTE_VENV_PATH=/remote/path/to/yaullm/.venv` in
`MetricsTestRunner/ae.env`. The remote worker also needs local access to the
model checkpoints referenced by `REMOTE_MODEL_PATH_*` and a writable
`REMOTE_OUTPUT_BASE`. It does not need to see the coordinator's local
`OUTPUT_BASE`.

Before running experiments, localize the cluster-specific settings in
`MetricsTestRunner/ae.env`. Do not edit the sweep script or the 16-GPU TOML
files for normal AE runs; the sweep injects these values into the TOML configs
at runtime.

```bash
cd "${AE_ROOT}/MetricsTestRunner"
cp ae.env.example ae.env
$EDITOR ae.env
source ae.env
```

Required values:

- `AE_ROOT`: parent directory containing the four AE repositories.
- `MODEL_PATH_30B` and `MODEL_PATH_7B`: local checkpoint paths. By default,
  TraceA, Coder, and ToolAgent use `MODEL_PATH_30B`; TraceB uses
  `MODEL_PATH_7B`. Override `MODEL_PATH_TRACE_A`, `MODEL_PATH_TRACE_B`,
  `MODEL_PATH_CODER`, or `MODEL_PATH_MOONCAKE` in `ae.env` if your package uses
  a different mapping.
- `DATASET_DIR`: local path to the anonymized trace directory.
- `WORK_DIR`: the `blitz-router` checkout, normally `${AE_ROOT}/blitz-router`.
- `VENV_PATH`: patched `yaullm` virtualenv, normally `${AE_ROOT}/yaullm/.venv`.
  Create it with `bash ae/setup_vllm_env.sh` if it is not already present.
- `OUTPUT_BASE`: where raw slow-path logs are written.
- `REMOTE_VENV_PATH`: patched `yaullm` virtualenv on the remote node. This may
  equal `VENV_PATH` on a shared filesystem, or be a remote-local path on a
  non-shared setup.
- `REMOTE_MODEL_PATH_30B` and `REMOTE_MODEL_PATH_7B`: model checkpoint paths as
  seen by the remote node. The per-trace remote overrides
  `REMOTE_MODEL_PATH_TRACE_A`, `REMOTE_MODEL_PATH_TRACE_B`,
  `REMOTE_MODEL_PATH_CODER`, and `REMOTE_MODEL_PATH_MOONCAKE` follow the same
  mapping as the local model variables.
- `REMOTE_OUTPUT_BASE`: writable output root on the remote node for remote vLLM
  logs.
- `REMOTE_HOST`, `REMOTE_USER`, `REMOTE_SSH_PORT`: SSH target for the second
  8-GPU node.

The sweep creates `blitz-router/exps/blitz-run/configs/config-stubs.json`
automatically when vLLM starts. It records the 8 local and 8 remote backend
HTTP endpoints consumed by the router.

Build the router and request simulator on the local coordinator. If your
artifact package lets either node act as the coordinator, run the same build on
that node before launching from there:

```bash
cd "${AE_ROOT}/blitz-router"
rustup toolchain install 1.88.0
cargo +1.88.0 build --release -p router --features lmetric-q -j "$(nproc)"
cargo +1.88.0 build --release -p request-sim -j "$(nproc)"
```

The first release build can take several minutes. In particular,
`request-sim` may compile vendored OpenSSL and other native dependencies. The
slow-path sweep invokes the same build with Cargo's quiet output, so a long
period with no terminal output during `Building request-sim client...` is
expected as long as `cargo`, `rustc`, or native compiler processes are active.

The `ae` sweep uses the current binary names:
`target/release/router` and `target/release/request-sim`.

Print the full experiment command list without launching the cluster:

```bash
cd "${AE_ROOT}/blitz-router"
bash ae/run_all.sh print-experiments
```

Print commands for a single figure group:

```bash
bash ae/run_experiments.sh print fig21
bash ae/run_experiments.sh print fig21a
bash ae/run_experiments.sh print fig22
```

After all paths, branches, policy arrays, and scaling-factor arrays have been
checked, run the whole GPU workflow:

```bash
cd "${AE_ROOT}/blitz-router"
bash ae/run_all.sh full
```

`ae/run_all.sh full` calls `ae/run_slow_path.sh all`. That script runs the
needed sweep indices one at a time, detects the newly generated
`OUTPUT_BASE/<timestamp>_<trace>_<policy>/attempt*/node1/client.jsonl`, links it
into `${AE_ROOT}/xmetric-plots/slow-data/<canonical-experiment-name>`, and then
regenerates Figure 21 and Figure 22 with:

```bash
XMETRIC_DATA_DIR="${AE_ROOT}/xmetric-plots/slow-data" \
  bash ae/run_figures.sh evaluation
```

The slow-path index-to-plot-data mapping is in `ae/slow_path_map.tsv`.

For long AE runs, it is usually better to execute figure groups separately:

```bash
bash ae/run_slow_path.sh fig21
bash ae/run_slow_path.sh fig22
```

Figure 21 subfigures can also be rerun independently:

```bash
bash ae/run_slow_path.sh fig21a  # ChatBot/Qwen
bash ae/run_slow_path.sh fig21b  # Agent/API Qwen
bash ae/run_slow_path.sh fig21c  # Coder
bash ae/run_slow_path.sh fig21d  # ToolAgent/Kimi
```

`sweep_test_robust.sh` accepts a zero-based `start_index` argument and honors
`SWEEP_TEST_LIMIT`. For example:

```bash
cd "${AE_ROOT}/MetricsTestRunner"
SWEEP_TEST_LIMIT=1 bash sweep_test_robust.sh 0    # run one test point
SWEEP_TEST_LIMIT=35 bash sweep_test_robust.sh 0   # run TraceA scaling block
SWEEP_TEST_LIMIT=28 bash sweep_test_robust.sh 105 # run ToolAgent scaling block
```

## Regenerating Figures Manually

To rerun plotting from archived fast-path data:

```bash
cd "${AE_ROOT}/blitz-router"
bash ae/setup_plot_env.sh
bash ae/run_figures.sh evaluation
```

To rerun plotting from slow-path data generated by `ae/run_slow_path.sh`:

```bash
cd "${AE_ROOT}/blitz-router"
XMETRIC_DATA_DIR="${AE_ROOT}/xmetric-plots/slow-data" \
  bash ae/run_figures.sh evaluation
```

`ae/setup_plot_env.sh` creates the plotting virtualenv at
`${AE_ROOT}/blitz-router/ae/.venv`, and `ae/run_figures.sh` uses that Python
automatically. If you run an individual figure script manually through
`ae/run_python_figure.py`, use the same venv:

```bash
cd "${AE_ROOT}/blitz-router"
bash ae/setup_plot_env.sh
ae/.venv/bin/python ae/run_python_figure.py \
  "${AE_ROOT}/xmetric-plots/figs/e2e-cdf-v1/qwen3-to-c.py"
```

Generated PDFs are written under `${AE_ROOT}/xmetric-plots/figs`.

The archived data-to-figure mapping is in `ae/evaluation_figures.tsv`. The full
GPU sweep index mapping is in `ae/sweep_index_map.tsv`, and the slow-path
canonical-data mapping is in `ae/slow_path_map.tsv`.

## Notes for Reviewers

- `ae/run_all.sh figures` is the shortest reproducibility check; it regenerates
  Figure 21 and Figure 22 from archived data without launching GPU jobs.
- `ae/run_all.sh print-experiments` prints the exact GPU commands and estimated
  runtime without launching any experiments.
- `ae/run_all.sh full` intentionally launches long-running 16-GPU experiments.
- `ae/run_figures.sh evaluation` regenerates only Figure 21 and Figure 22.
- Some upstream batch scripts were used as experiment notebooks. The target
  matrix above, `ae/evaluation_figures.tsv`, and `ae/sweep_index_map.tsv` define
  the AE results to reproduce.
